## 主要变更

- **记录查询页签**：统计卡下方新增「记录查询」，按范围与类型读取保留期内的记录，不再受最近 200 条上限；查询按日文件分片读取，时间片耗尽时保留位置可续扫，已发布的快照不再改变，列表用游标分页；详情按文件、行偏移与行指纹重新读取，文件被改写或清理后报「记录不可用」而不是给错的数据（提交 9a68820）。
- **匿名未知证据与检测状态**：记录新增匿名未知证据——未知标记只留请求内编号和白名单 kind，不保存模型写的标记文本；检测状态分成「设置」与「实际执行」，没检测过的显示为未检测，不再显示成零风险。外带仍按既有语义计数，界面文案改为「外带风险命中」（提交 9a68820）。
- **修复：网关重载不再让进程内请求全部失败**：卸载（改配置、重载、重建产物）时不再把安装时捕获、随后被邻居插件关闭的 dispatcher 交回全局槽，重装也不再把这种已关闭的层当作下游。此前邻居插件换代叠加一次网关重载，会让进程内所有走全局 `fetch` 的 provider（包括从不使用那个插件的）报死层自己的错误，只能重启恢复（#9、#10）。
- **修复：配置页在卸载重装后不再 404**：Remote 服务改为在 `apply()` 内同步挂载，不再与旧 fiber 的销毁赛跑。此前不重启的卸载重装会让脱敏照常工作而 `/api/privacyGateway/*` 全部 404，配置页拿不到数据（提交 2c21c67）。
- **内部**：ADR-0012 补充「交回与安装都要落在活层上」，写明新建 `Agent` 兜底会丢掉用户代理配置这一取舍；新增三条 dispatcher 回归测试。

## English

- **Record query tab**: a new "records" query under the stats card reads the retained records by range and type instead of only the latest 200. Slices read the per-day files, keep their place when a time slice runs out, never mutate a published snapshot, and paginate with a cursor. Details are re-read by file, row offset and row fingerprint; a rewritten or cleaned file reports the record as unavailable instead of returning wrong data (commit 9a68820).
- **Anonymous unknown evidence and detection state**: records gain anonymous unknown evidence — an unknown marker keeps only its in-request number and a whitelisted kind, never the model-written marker text. Detection is split into configured and actually executed, so a record that was never inspected no longer shows up as zero risk. Exfiltration still counts under the existing semantics, and the UI wording is now "exfiltration risk hit" (commit 9a68820).
- **Fixes: a gateway reload no longer takes every request in the process down**: unloading (a configuration change, a reload, a rebuilt artifact) no longer hands the global slot a dispatcher it captured at install time that a neighbouring plugin has since closed, and installing no longer adopts such a closed layer as its downstream. Before this, one neighbour generation swap plus a gateway reload made every provider on the global `fetch` — including ones that never use that plugin — fail with the dead layer's own error, until a restart (#9, #10).
- **Fixes: the settings page no longer 404s after an uninstall and reinstall**: the Remote service is mounted synchronously inside `apply()` instead of racing the old fiber's teardown. Masking kept working while every `/api/privacyGateway/*` call returned 404, so the page had no data (commit 2c21c67).
- **Internal**: ADR-0012 now records that both handback and install must land on a live layer, including the trade-off that a fresh `Agent` drops the user's proxy configuration; three dispatcher regressions were added.
