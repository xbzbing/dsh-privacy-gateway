## 主要变更

- **修复：插件自己的 WebSocket 与 `CONNECT` 连接不再被拦**：网关以前对所有升级连接一律拒绝（升级后的字节流绕过 dispatcher，无法脱敏），于是 dsh-im-infoflow 这类插件在模型调用之外建的入站连接永远建不起来——`/status`、卡片提交、单聊/群聊消息全部收不到，而它的出站走普通 HTTPS 不受影响，所以卡片照常能发出去，故障只体现在「发得出去、收不回来」。现在只在模型调用（`llm/stream` 上下文）里拒绝，调用外放行、消息不脱敏，每个 host 只提示一次；明确放行（`/privacy off`、`enabled` 关、排除的 provider、关闭了脱敏的会话、`excludeHosts`）仍先于调用判定。这是 fail-closed 往 fail-open 的取舍，代价（保护范围从「所有升级」缩到「经过 `llm/stream` 的升级」）与被否的备选都记在 ADR-0032。
- **内部**：`CallContext` 换成可判别联合（排除的 provider / 模型调用），两种上下文不再可能同时成立；`unbypassing` 改名 `asModelCall`。新增 ADR-0032，ADR-0025 补记指针。

## English

- **Fixes: a plugin's own WebSocket and `CONNECT` connections are no longer refused**: the gateway used to refuse every upgraded connection (after an upgrade the bytes bypass the dispatcher, where they cannot be masked), so an inbound connection a plugin such as dsh-im-infoflow opens outside a model call never came up — `/status`, card submissions and chat messages were all lost, while its outbound traffic over plain HTTPS was unaffected, which is why cards still went out and the failure showed up only as "sends fine, receives nothing". An upgrade is now refused only inside a model call (the `llm/stream` context); outside one it is let through, its messages unmasked, with one notice per host. Explicit bypasses (`/privacy off`, `enabled` off, an excluded provider, a session with masking off, `excludeHosts`) still win over the call check. This is a fail-closed to fail-open trade: its cost (protection narrowed from "all upgrades" to "upgrades through `llm/stream`") and the rejected alternatives are recorded in ADR-0032.
- **Internal**: `CallContext` is a discriminated union now (an excluded provider's stream or a model call), so the two can no longer hold at once; `unbypassing` is renamed `asModelCall`. New ADR-0032, with a pointer added to ADR-0025.
