## 主要变更

- **首个正式版**：进程级脱敏网关，装在宿主进程的 undici 全局 dispatcher 上。所有走 `fetch()` 的 provider 在同一个点被拦截与还原，插件带的 adapter 也一样，agent 和 provider 不用改。
- **出站换占位符，入站换回原值**：密钥、令牌、私钥、URL 里的密码、`Cookie` 头、个人信息与自定义敏感词在请求体里换成占位符；回复（包括 SSE 流）里的占位符换回真值。`<env>` 块与工具定义逐字节原样发出，prompt cache 照常命中。
- **不落真值**：记录、统计、日志与「发出内容」副本里只有占位符和首尾几个字符；脱敏出错时请求不发出。
- **可查可控**：`/privacy` 命令、会话里的「隐私保护」标签页、按天的统计与明细、按会话关闭脱敏、按 provider 排除。

## 安装

```bash
# 正式版（npm）
dsh plugin --profile web add dsh-privacy-gateway@0.1.0

# 同一版本的 GitHub Release 附件

```

## What changed

- **First stable release**: a process-wide redaction gateway on the host process's undici global dispatcher. Every provider that goes through `fetch()`, including adapters that plugins bring, is intercepted and restored at one point; no agent or provider changes.
- **Placeholders out, real values back**: keys, tokens, private keys, passwords in URLs, `Cookie` headers, personal data and custom words become placeholders in request bodies; placeholders in the replies, SSE streams included, are turned back into the real values. `<env>` blocks and tool definitions are sent byte for byte, so the prompt cache still hits.
- **No real value is ever stored**: records, stats, the log and the "what was sent" copy hold only placeholders and a few characters at each end. When masking fails, the request is not sent.
- **Visible and controllable**: the `/privacy` command, the 「隐私保护」 tab in a session, per-day stats and details, masking turned off per session, and providers excluded one by one.
