## 主要变更

- **记录能回到会话里的那一步**：统计卡每条记录多一列「轮·步」（如 `42·3`），明细里写全「这次请求在第 42 轮 · 第 3 步发出」，编号与「轨迹」标签页完全一致，看到可疑记录可以直接跳过去核对。此前只有时间和会话标题，同一轮里发好几个请求时分不清是哪一次（ADR-0030）。每个值下面还会写「值首次被发出：第 42 轮 · 第 2 步」，回答「这个值是第几步漏出去的」——注意记录本身记的是**发出**的那一步，值可能来自更早一步，界面把这件事写明了。
- **一个值出现过的每一处都记下来**：同一个值在一段历史里出现多次时，记录列出每一处（最多 8 处，再多只计数），界面按「用户消息 · `messages.3`」标出它在那次请求的哪条消息里，配前后各约 80 个字符。原先只记第一处，长会话里同一个值反复外发时看不出全貌（ADR-0028）。
- **JSON 键也脱敏**：`{"metadata": {"sk-…": …}}` 这种把密钥当键名的请求，键名也会换成占位符，回复里再换回来；记录里写的是发出时的占位符，不再带原始键名。协议自身的键（`model`、`role`、`type`、`name`、`id` 等）、工具定义和工具调用的参数名永不动，否则供应商读不懂请求。新增配置项 `maskKeys`，默认开，配置页可关（关闭有二次确认）（ADR-0029）。
- **修复：短口令与「占位写法」不再算作值**：短于 8 个字符的秘密（`abc123`、`666666`、`888888`）原样发出、不进记录——它们随时能被爆破，遮住只是给一个并不存在的保护，而值表本来也不把这么短的值当作已知值。8 个以上相同字符连排（`sk-proj-xxxx…`、`AKIA0000…`）或自带 `your_api_key`、`example`、`changeme` 之类说明的写法同样不算值。此前写一个假 key 排查问题，统计卡会显示「替换 1」，数字虚高（ADR-0031）。`sk_test_…` 这种真测试 key 照旧脱敏。
- **内部**：短口令的下限与值表的 `MIN_KNOWN` 取同一个数，两处不再自相矛盾（有一条断言盯着相等）；占位模板的检查只看值的首尾各 128 个字符，把病态输入（8000 个 `token=`）的耗时从 154 ms 压到 73 ms，守住 `test/linear.test.ts` 的预算。

## English

- **A record now names the step it came from**: each record carries a 「轮·步」 (turn · step) column (`42·3`) and the details spell it out — this request went out in turn 42, step 3 — numbered exactly as the 「轨迹」 (Trajectory) tab numbers them, so a suspicious record can be found there directly. Before, a record had only a time and a session title, and a turn that makes several requests was hard to pin down (ADR-0030). Every value also says where it was first sent (turn 42, step 2), which answers "which step let this value out" — the record itself names the step that **sent** it, and a value may come from an earlier one; the card says so.
- **Every place a value went is recorded**: when one value appears many times in a history, the record lists each place (eight at most, the rest counted), and the card names the message it sat in (「用户消息 · `messages.3`」) with about 80 characters of context on either side. It used to keep only the first place, so a value sent over and over in a long session was only partly visible (ADR-0028).
- **JSON keys are masked too**: in a body that uses a secret as a key (`{"metadata": {"sk-…": …}}`), the key becomes a placeholder as well and is put back in the reply; the record keeps the placeholder as it went rather than the raw key. Keys that are part of the protocol (`model`, `role`, `type`, `name`, `id` and the like), tool definitions and tool call argument names never change, or a vendor cannot read the request. There is a new `maskKeys` setting, on by default, and it can be turned off on the Configure page (with a confirmation) (ADR-0029).
- **Fixed: short passwords and "placeholder" values are no longer counted**: a secret shorter than 8 characters (`abc123`, `666666`, `888888`) goes as written and makes no record — it is guessed in no time, so masking it promises a protection that is not there, and the value table never matched anything that short as known. Eight or more of one character in a row (`sk-proj-xxxx…`, `AKIA0000…`), or a value that says what it is (`your_api_key`, `example`, `changeme`), is no value either. Writing a fake key to debug used to show "1 replaced", inflating the numbers (ADR-0031). A vendor's real test key (`sk_test_…`) is still masked.
- **Internal**: the short-secret floor now uses the value table's own `MIN_KNOWN`, so the two no longer disagree (an assertion pins them equal); the placeholder check reads only the first and last 128 characters of a value, which brings a pathological input (8000 `token=`) from 154 ms down to 73 ms and keeps `test/linear.test.ts`'s budget.
