## 主要变更

- **修掉具名规则的误伤**：`export const GATEWAY_CREDENTIAL_HEADER = 'x-…'` 这类源码常量——字段名里带 `credential`、值是小写连字符分段的头名——不再被当成密语脱敏（#4）。以前它会被换掉，`shape` 打开时换成同形假名，评审 agent 据假值得出「这个头名随机不可读」的错误结论并公开发表，同一个文件用 `xxd` 读又能解出真值，两种读法不一致；现在判断跟着**字段名的末位词**走：末位是容器词（`header`、`id`、`uuid`、`file`、`path`、`name`、`url`、`uri`、`label`、`prefix`、`suffix` 及其复数）且值是 slug（全小写、只按 `-` `_` 分段、每段短于 16 字符）时，值是名字，原样发出（[ADR-0038](docs/adr/0038-container-field-slug-values.md)）。
- **放行面是闭合词表，不是「末位词不是密语词」的反向判定**：`DB_PASSWORD`、`SECRET_V2`、`clientsecret`、`DB_PASSWORD_HASH`、`credential_phrase` 这类字段名下的值一律仍遮，词表外的末位词不会漏遮；值含数字或大写、单段 ≥16 字符的口令不受影响（[ADR-0036](docs/adr/0036-named-field-values.md) 的门槛不变）。容器字段名 + 恰好小写分段无数字的真实口令是残余漏报面，README 能力边界已写明，兜底仍是 `allow`。
- **README 补「能力边界 / 不负责的事」两节**：写清漏检面（规则没命中的密钥、hex 与分行的编码旁路）、误伤面（具名规则的源码常量）、不负责的事（不拦工具拿到真值之后的动作、不跨进程共享值表、不做合规认证、不做静态数据保护）——判断「这段内容到底有没有被保护到」时照这两节，不再逐条翻 ADR。
- **内部**：容器词表 `CONTAINER_WORDS` 与 `SECRET_WORDS` 导出给守卫用例——12 个基词及其复数共 24 条逐条断言「容器字段名 + slug」放行，集合与写死的清单精确比对，并断言两词表不相交；以后往词表加 `hash`、`value`、`phrase` 之类的词会先让用例失败，原样发出的面不会静默扩大。

## English

- **Fixed the named-rule false positive**: a source constant like `export const GATEWAY_CREDENTIAL_HEADER = 'x-…'` — the field name contains `credential`, the value is a lower-case hyphenated header name — is no longer masked as a secret (#4). It used to be replaced, and with `shape` on it became a same-shape fake, so a reviewing agent concluded "this header name is randomly unreadable" and said so publicly while `xxd` on the same file still read the real value — two readings that disagree. The decision now follows the field name's **last word**: when that word is a container word (`header`, `id`, `uuid`, `file`, `path`, `name`, `url`, `uri`, `label`, `prefix`, `suffix`, and their plurals) and the value is a slug (all lower case, split only on `-` `_`, each segment under 16 characters), the value is a name and goes as written ([ADR-0038](docs/adr/0038-container-field-slug-values.md)).
- **The allowed surface is a closed list, not "the last word is not a secret word"**: values under `DB_PASSWORD`, `SECRET_V2`, `clientsecret`, `DB_PASSWORD_HASH`, `credential_phrase` keep being masked — a last word outside the list can never let one through; a value with a digit or a capital, or a single segment ≥16 characters, is unaffected (ADR-0036's threshold stands). A real lower-case hyphenated digitless passphrase under a container field name is the residual miss, written up in the README's capability boundary; `allow` remains the fallback.
- **README gains "What it does not cover" and "What it does not do" sections**: the miss surface (secrets no rule matches, hex and line-broken encodings pass by construction), the false-positive surface (named rules on source constants), and what is out of scope (actions after a tool holds the plaintext, no cross-process value table, no compliance certification, no static-data protection) — consult these two sections for "was this content covered", instead of reading every ADR.
- **Internal**: `CONTAINER_WORDS` and `SECRET_WORDS` are exported for a guard test — 24 rows assert "container field name + slug" passes for all 12 base words and their plurals, the set is compared exactly against a list written out in the test, and the two word lists are asserted disjoint. Adding `hash`, `value` or `phrase` to the list fails the test first, so the surface that goes as written cannot silently widen.
