## 主要变更

- **放行的 provider 有请求发出时，日志里提示一次**：`excludeProviders` 里勾掉的 provider 的请求照旧原样发出——不脱敏、回复不还原、不留记录，这点没变；但此前这条路完全无声，记录和统计里都看不到，事后只能凭勾选状态猜真值有没有出去。现在只要有本该脱敏的请求真的从它那里发出，网关就写一条只含 provider id 的 warn，同一个 provider 每次运行提示一次；日志里没有真值（ADR-0034）。
- **内部**：新增 ADR-0034，ADR-0018 的后果里补了指向它的一条；dispatcher 把「本该脱敏的请求」与「放行判定」拆开（`#maskable` + `#passes`），放行时才写这条 warn；配置页说明与 README 中英同步。

## English

- **A masked-off provider now says so once in the log**: requests of a provider in `excludeProviders` still go out as they are — nothing masked, no placeholder restored, nothing recorded — and that has not changed; but the path used to be silent, invisible in both the records and the stats, so the only way to tell whether real values had left was to look at the checkbox. Now, when a request that would have been masked really goes out from such a provider, the gateway writes one warn naming the provider id, once per provider per run; no value is in the log (ADR-0034).
- **Internal**: ADR-0034 added, with a pointer from ADR-0018's consequences; the dispatcher now tells "a request that would be masked" apart from "a bypass" (`#maskable` + `#passes`) and writes the warn only on the bypass; the Configure page's hint and both READMEs say so.
