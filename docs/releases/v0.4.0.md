## 主要变更

- **堵住请求脱敏绕过**：Blob、ArrayBuffer、带偏移的视图、同步和异步 iterable 等合法 JSON body 统一完整读取后脱敏；multipart 放行校验稳定属性与原生内部 brand，不能靠 FormData 名称、原型、getter 或 Proxy 伪造。模型候选 JSON 中同一对象的重复键在脱敏副作用前拒绝，普通字段不再因点分路径被误当成工具定义或宿主 `<env>`（#8）。
- **审计不再带出被脱敏原值**：warn JSON 键及后代路径、protected 区域附近的记录上下文、model/host/session/标题和外带 host 都使用独立安全投影；包括非规范 Unicode 转义和热更新后的输出。warn/block 命中进入有界审计专用内存记忆，但不会因此参与后续请求脱敏或回复还原；协议占位符与同形假 key 保持完整，不被短敏感词再次改写（#8）。
- **工具外带守卫覆盖完整参数**：对象参数的键和值一起判定；SSE 只拼接同一调用、同一字段的片段，空字符串/对象/数组不提前放行，实际尾片还原与守卫共用调用身份。厂商协议的签名字段仍按原有规则保持字节；工具参数中的外部目标不会因字段名相同而被判定漏掉（#8）。守卫仍只覆盖可识别的 URL/scp 外部 host，不能拦住所有间接外带。
- **取消、背压和卸载可靠收敛**：读取 body 期间即可取消；压缩回复的 pause/resume/abort 和 write/drain 向解压层传播，HTTP 输入结束后仍有效。记录完成失败不再吞掉响应的成功或失败终结；卸载保留可交还的 proxy/fallback，失败可重试（#8）。
- **记录恢复和首次预览修复**：坏记录逐行隔离，跨日重复 key 只保留第一条合法读取，实时记录优先；生成和恢复使用同一安全键范围，旧记录补键不冲突。`/privacy test` 第一次就应用已保存的新配置，blocked 尝试不再记成首次已发送（#8）。
- **升级注意事项**：为保证读取期立即取消和一次开始通知，请求回调现在提前收到稳定 context 对象；下游 object context 合并并保留 redirect history，`controller.context` 可读取下游原始 null/基本类型，但提前回调第二参数不再保证与晚到值严格相等。默认 `restoreLog=false` 与占位符协议不变。vendorView 的受保护区域、allow 与未命中内容仍可能含敏感原文；本版不自动改写或删除旧日志/JSONL。
- **内部**：发布流程把已有 tag 的 peeled Commit 绑定到 checkout HEAD，稳定版补发包须匹配已发布 npm 包的完整性摘要，防止给旧 tag 附上新来源的产物。现有 ADR 和中英文说明补充了实际边界，没有新建 ADR（#8）。

## English

- **Closed request-masking bypasses**: valid JSON bodies carried by Blob, ArrayBuffer, offset views, and synchronous or asynchronous iterables are collected before masking. Multipart exemptions require stable properties and a native internal brand, not a spoofed FormData name, prototype, getter or Proxy. Duplicate keys in the same object of a model candidate are rejected before masking side effects; dotted ordinary keys are no longer mistaken for tool definitions or host `<env>` regions (#8).
- **Masked originals stay out of audit output**: warned JSON keys and descendant paths, record context near protected regions, model/host/session/titles and exfiltration hosts use independent safe projections, including noncanonical Unicode escapes and output after live configuration changes. A bounded audit-only memory retains warn/block hits without granting later wire masking or reply-restoration authority. Protocol placeholders and same-shape stand-ins remain intact instead of being rewritten by short sensitive words (#8).
- **Tool guards inspect complete arguments**: object keys and values participate in the decision. SSE fragments concatenate only within the same call and field; empty strings, objects or arrays do not release held arguments, and actual tail restoration shares the guard's call identity. Vendor-protocol signature fields retain their bytes under the existing rules; external destinations in tool arguments are not ignored merely because a field has the same name (#8). The guard still detects only recognized URL/scp external hosts, not every indirect exfiltration path.
- **Cancellation, backpressure and disposal settle reliably**: calls can be cancelled during body collection; compressed replies propagate pause/resume/abort and write/drain through decoding, even after HTTP input ends. Recording failures no longer swallow the response's success or failure terminal callback. Disposal retains a handback proxy/fallback and can be retried after failure (#8).
- **Record recovery and first previews fixed**: malformed rows are isolated, duplicate keys across days retain the first valid row read, and live records take priority. Generation and recovery use the same safe key range, with collision-free keys for legacy rows. The first `/privacy test` uses the saved live configuration, and a blocked attempt is no longer recorded as the first sending (#8).
- **Upgrade note**: immediate cancellation with one start notification requires an early stable context object. Downstream object context is merged with redirect history preserved; `controller.context` exposes the original downstream null or primitive value, but the early callback's second argument no longer has strict identity with that later value. `restoreLog=false` and the placeholder protocol remain unchanged. Protected, allow-listed and unmatched vendorView content may still contain sensitive originals. This version does not automatically rewrite or delete old logs/JSONL.
- **Internal**: release checks bind an existing tag's peeled Commit to checkout HEAD and require a resumed stable-release artifact to match the already-published npm integrity digest. Existing ADRs and bilingual documentation clarify the boundaries; no new ADR was added (#8).
