# ADR-0016：厂商视角对照：内存里留发出的 body，不出真值

- 状态：Accepted（2026-10-31）
- 相关：`src/views.ts`、`src/engine.ts`、`src/remote.ts`、`src/client/VendorView.ts`、设计 §7.5、§13 R14

## Context

magpie 的「观测 › 脱敏」页把脱敏前后的请求左右并排，用户能直接核对厂商看到了什么、遮蔽有没有动到不该动的地方。要做到这点就得每个请求留一份 body 副本，内存代价大（R14）。另一个问题是脱敏前的原文含真值：放进 RPC 送到浏览器，统计界面「从不出现值」的约定就破了（ADR-0008、ADR-0011）。

## Decision

- 配置 `vendorView`，默认关。开启后，每条记录（只有脱敏或还原过的请求才有记录）在内存里留一份实际发出的 body，按记录 key 索引。上限照 magpie：最多 100 份，单份超过 4 MiB 不留，总量 64 MiB，超了从最老的删。不落盘，重启即清空。被 block 拦下的请求没有发出，不留。
- 留下的是厂商收到的那份，只有一处改动：warn 动作照发的值换成它本该有的占位符，所以副本里没有任何真值。
- 新增 Remote 方法 `privacyGateway/vendorView({ key })`，返回 `{ key, body }` 或 `null`；`overview` 多返回 `vendorView`、`views`（留有副本的记录 key）。
- 界面的「左右对照」：右边是厂商视角，原样显示发出的 body，占位符和假 key 高亮；左边是 agent 视角，同一份 body 里每个替换处换成「kind · 开头… · 长度」的标记，而不是真值。默认只列有替换的行。

## Consequences

- 左边不是真正的原文。要核对的是「哪些位置被换了、换成了什么」，这用标记就够；需要看真值时去看会话日志（ADR-0003）。
- 开启后最坏多占 64 MiB 内存。
- 副本里仍有用户的提示词、代码和工具输出，和会话日志同等敏感，只是不含被遮掉的值。RPC 走 dsh 的 `/api` 通道，访问控制与其他 Remote 服务相同。
