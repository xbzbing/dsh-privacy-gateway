# ADR-0016：厂商视角对照：受限的已发出 body 内存副本

- 状态：Accepted（2026-10-31）
- 相关：`src/views.ts`、`src/engine.ts`、`src/remote.ts`、`src/client/VendorView.ts`、设计 §7.5、§13 R14

## Context

magpie 的「观测 › 脱敏」页把脱敏前后的请求左右并排，用户能直接核对厂商看到了什么、脱敏有没有动到不该动的地方。要做到这点就得每个请求留一份 body 副本，内存代价大（R14）。另一个问题是脱敏前的原文含真值：放进 RPC 送到浏览器，统计界面「从不出现值」的约定就破了（ADR-0008、ADR-0011）。

## Decision

- 配置 `vendorView`，默认关。开启后，每条记录（只有脱敏或还原过的请求才有记录）在内存里留一份实际发出的 body，按记录 key 索引。上限照 magpie：最多 100 份，单份超过 4 MiB 不留，总量 64 MiB，超了从最老的删；大小按 UTF-8 字节计，中文内容也不会超出这个量。不落盘，重启即清空。被 block 拦下的请求没有发出，不留。
- 留下的是厂商收到的那份，再将 warn 动作照发的值（含 JSON 键）换成它本该有的占位符；占位符和假 key 保持完整，不再次替换其公共协议片段。副本仍可能包含受保护区域、allow 与未识别内容的敏感原文，不是无秘密的安全导出（见下文例外）。
- 新增 Remote 方法 `privacyGateway/vendorView({ key })`，返回 `{ key, body }` 或 `null`；`overview` 多返回 `vendorView`、`views`（留有副本的记录 key）。
- 2026-10-31 修订：`vendorView` 与 `overview` 每次调用都先读当前配置。配置页关掉 `vendorView` 后，下一次调用就返回 `null`、清空已存的副本，不等下一个模型请求。
- 界面的「左右对照」：右边是厂商视角，原样显示发出的 body，占位符和假 key 高亮；左边是 agent 视角，同一份 body 里每个替换处换成「kind · 开头… · 长度」的标记，而不是真值。默认只列有替换的行。

## Consequences

- 左边不是真正的原文。要核对的是「哪些位置被换了、换成了什么」，这用标记就够；需要看真值时要把 `restoreLog` 打开，会话日志里才会有（ADR-0003）。
- 开启后最坏多占 64 MiB 内存。
- 副本里仍有用户的提示词、代码和工具输出，和会话日志同等敏感，只是不含被换掉的值。RPC 走 dsh 的 `/api` 通道，访问控制与其他 Remote 服务相同。
- 受保护区域（`<env>` 块、工具定义，ADR-0004）逐字节原样发出。一个被脱敏的值如果出现在那里，厂商收到的就是原文，副本里也照样是原文：副本只是如实反映发出的内容，厂商本来就收到了它。

### 补充（2026-11-28）：stream 保留 adapter 前的结构化请求

ADR-0040 的 stream 半也支持 `vendorView`。dispatcher 副本仍是实际 wire body；stream 没有 adapter 最终序列化后的 body，因此保存的是本插件重新派发的结构化请求，不能把它称作最终线上内容。序列化快照排除 `AbortSignal`，无法安全序列化时不留副本、不影响模型请求。

两种副本共用同一个 `ViewStore`、记录 key、warn 值及键名投影和容量限制，切换 `intercept` 不清空已有副本，关闭 `vendorView` 仍立即清空。界面与随包文档明确区分两种格式。
