# ADR-0035：统计卡的 kind / finder 释义与明细筛选

- 状态：Accepted（2026-11-11）
- 相关：`src/client/StatsParts.ts`、`src/client/StatsCard.ts`、`src/client/view.ts`、`src/client/locales.ts`、`src/client/styles.ts`、`src/client/primitives.d.ts`、ADR-0011、ADR-0024

## Context

统计卡有两张按 kind 和 finder 的分布图，明细表也有 kind、finder 两列。这两个词是插件内部的术语：kind 是值的类别（占位符按它命名），finder 是认出这个值的查找器；README 里有对照表，界面上却只有单词本身。维护者第一次看到 SECRET 50,578 与 known 23,034，问的就是这两个词和这两组数是什么关系。

同一张卡还有两处会让人停一下：

- 分布图每栏最多列 6 条，其余在内部被加总成一行，标签是省略号 `…`——看上去像「还在加载」或「更多」，不知道它是一行真实数据。
- 明细表一条请求最多列 200 个值（每轮都会重发历史），想只看某一类值只能逐行找。

约束：界面只用官方控件（`@deepseek-ai/dsh-client-ui-primitives`）与主题变量；文案中英两本字典键与占位符对齐（有测试）；不引入运行时依赖；不改记录格式、统计口径与 host 行为；client 包仍然由 esbuild 打成 `lib/client.js`。

### 被否的备选

- **用 `Tooltip` 显示说明。** 否：说明包含定义和一段名字清单，一行字符串放不下；Tooltip 的泡泡不能把指针移进去读。
- **只在 README 里补一段解释。** 否：README 已经写了，问题恰恰是看卡片的人不会回去翻。
- **分布图标题直接用长标题**（例如「按 kind（值的类别）」）。否：三栏宽度有限，长标题会挤掉条目；释义还包含每个名字的一句话，塞不进标题。
- **在明细表里按占位符搜索。** 否：用户要按类别缩小范围，不是按某个值；占位符本身是随机哈希，搜不出来。
- **筛选做成跨记录的全局条件。** 本次不做：记录列表的行上没有 kind / finder 列，全局筛选要在卡片顶部再加一排控件，并把「哪些记录算命中」定成新的统计口径；先解决明细表里逐行找的问题。

## Decision

- 「按 kind」「按 finder」两张分布图的标题旁加一个 info 图标，整个标题是官方 `HoverCard` 的锚点，卡里是这个维度的定义和计数口径（「数字是替换处数，不是请求数；warn / block 不计入」）。
- 分布图里的每个条目名（`SECRET`、`known` 等）各自是 `HoverCard` 的锚点，卡里是这个名的解释；「其余 kind / finder / host」这类合计行和 host 的条目不挂卡。
- 官方 `HoverCard` 的卡片背景固定为深色（`#2C2C2E`）却不设文字颜色，浅色主题下内容继承页面的黑色，会看不清；卡内文字用壳自己悬停卡的浅色（标题 `#fff`、说明 `#cfd3d6`），不跟随主题变量。
- 官方 `HoverCard` 的包裹层是 `display:block`，卡片本身固定 244px 宽（内容约 212px）。因此放卡的标题容器改成 flex，让包裹层收缩到标题宽度、卡片贴着标题出现；卡里只放两三行文字，术语解释拆成每个名字一张小卡，不在一张卡里排两列术语表。
- 明细表的 kind、finder 列头改成筛选按钮（官方 `Menu`），同时是悬停说明的锚点（卡里只有定义，不放术语表）：按钮本身列出该条记录里出现过的名字和「全部」，选中后只列这一类值；两列同时生效（取交集），选「全部」取消；一条都不剩时显示「没有符合筛选的值」。筛选状态跟着那一条记录的行走（收起再展开仍保留），换页后行被重新创建，回来时从「全部」开始；筛选只影响显示。
- 名字到释义的映射放在 `src/client/view.ts`（纯函数 `kindHintKey` / `finderHintKey`），`KIND_NAMES` / `FINDER_NAMES` 列出这个版本写的全部名字；不认识的 kind / finder（别的版本写的记录）不挂卡。
- 分布图第 7 行的标签不再用 `…`，按维度写成「其余 kind / 其余 finder / 其余 host」（英文 Other kinds / finders / hosts），经 `bars()` 的 `others` 参数传入。
- 变动的界面元素都用 `--dsw-alias-*` 主题变量与 `--ds-font-family-code`，不加新依赖；host 半、记录格式、统计口径与 Remote 返回值都不动。

## Consequences

- 这两个词在卡片里自解释；新增 kind 时若忘了补释义，`test/card.test.ts` 的「每个 kind 与 finder 都有中英释义」会红。
- `KIND_NAMES` 与 README 的脱敏范围表是两份手工维护的清单，加 kind 时两处都要改（测试只能保证界面有释义，不能保证与 README 同步）。
- HoverCard 只认指针，键盘用户拿不到这条说明；它是解释性内容，不影响任何操作，因此接受。
- 官方卡片宽度固定（244px，内容约 212px），卡里的文案要按这个宽度写；包裹层是块级，放在块级容器里会撑满整行，需要 flex/行内布局让它收缩到锚点宽度——这两点是使用该组件时容易踩到的。
- 卡片依赖宿主 `@deepseek-ai/dsh-client-ui-primitives` 导出 `HoverCard`。当前 dsh 的 `client` 平台种子有这个导出（侧栏会话行的悬停卡就是它）；更老的宿主若没有，`StatsCard` 会在渲染这条悬停卡时出错，这是本决策接受的版本下限。
- 明细表的筛选不改变记录、统计和「查看发出内容」；状态跟着那条记录的行，收起再展开仍在，换页回来则重新从「全部」开始。
