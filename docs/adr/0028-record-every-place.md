# ADR-0028：记录一个值出现过的每一处，界面按消息序号标出

- 状态：Accepted（2026-11-02）
- 相关：`src/records.ts`、`src/client/view.ts`、`src/client/StatsParts.ts`、`src/client/locales.ts`、`src/client/styles.ts`、ADR-0008、ADR-0024

## Context

ADR-0024 让每个值带上它第一次出现的位置和前后文字，定位前进了一步，但仍有缺口：

- 界面只知道第一次出现的位置，并且只有位置标签（「用户消息」）可见，路径只在悬停时作为 tooltip 出现。用户想「这条记录里的 `sk-…` 到底发在第几轮对话」，需要读 tooltip 里的 `messages.3.content.0.text`，把点分路径自己翻译成消息序号。
- 同一个值出现在多处时，记录只留第一处，其余只加进 `n`。用户看到「4 次」，但看不到另外 3 处在哪。上下文片段也取自第一处，未必是用户关心的那一处。

轮次、步数不解决这个问题：请求本身一轮一次，而被关注的是值在请求 body 里的位置。每轮都把整段历史重发一遍，所以同一个值会随着对话推进出现在越来越多的消息里，位置本身才是答案。

## Decision

- 记录里的每个值多一个字段 `elsewhere`：除第一处（`at`）之外，它在这个 body 里出现过的其他位置，按出现顺序，格式与 `at` 相同（点分路径 + 内层对象的 `role`/`type`）。
  - 只记没见过的路径：同一路径重复出现只累进 `n`，不进 `elsewhere`，也不计入溢出。
  - 一个值最多记 `MAX_RECORD_PLACES`（8）处，`at` 算一处；超出的**不同位置**按处累进 `elsewhereOmitted`，与 `valuesOmitted` 同样的溢出写法。因此 `at` 加 `elsewhere` 最多 8 处，`1 + elsewhere.length + elsewhereOmitted ≤ n`。
  - 只在不止一处时写 `elsewhere`；只有一处（多数情况）时记录与原来逐字节相同。
- 界面：位置标签里直接带上消息序号，形如「用户消息 · `messages.3`」，路径部分用等宽字体；tooltip 仍然是完整路径。有其余位置时，再一行「还出现在 `messages.7`、`messages.9`（另有 N 处没列出）」，同一消息里的多处只列一次。
- 序号只取「首段 + 紧跟它的下标」：`messages.3.content.0.text` 读作 `messages.3`，`contents.1`、`input.0`、`system.0` 同理；首段不是列表的路径（`prompt`、`systemInstruction.parts.0.text`）整段只显示首段，因为那里没有消息序号，凑一个出来只会指错地方。下标是请求 body 里的数组下标，从 0 起算，与「查看发出内容」里看到的 body 是同一套坐标，不换算成「第几条」。这层解析放在 client 的 `placeLabel` 里，host 端只记完整路径。
- 界面自己再兜一层：只保留能画出名字的值、字段按类型取值、其余位置最多列 7 个（多出的并入计数），路径去重。记录文件可能来自别的版本，卡片不能因为它形状不对就画不出来或报错。
- 沿用 `recordContext` 开关，不新增配置项：位置信息本来就是它管的，`at` 不记时 `elsewhere` 也不记。新增页面字段还得同步 `config.ts`、`client/fields.ts`、`locales.ts` 并在 `test/fields.test.ts` 里对上，为一个「开关关了连 `at` 都没有」的字段付这份代价不值得（ADR-0021）。

## Consequences

- 定位一个值从「读 tooltip 再自己换算」变成「直接看到第几条消息」，多处出现时其余位置也直接列出。
- **先到先得，被丢掉的恰恰是最新的位置**：超过 8 处时保留的是最先遇到的，后来的只计数。长会话里同一个值可能最早出现在开头的用户消息、最新的出现在刚发生的那条，此时最新那条只出现在数字里。选 8 是因为一行放得下 7 个等宽路径，且每处约 50 字节：一条记录最多 200 个值，全挤满时从约 70 KB 涨到约 140 KB，仍在 `keepMegabytes` 的修剪范围内；多数值只出现一处，实际增量为零。
- 记录体积：`at` 之外每处约 40–60 字节，每值最多 7 处，且只在多处出现时才有。仍受 `valuesOmitted` 与 `keepMegabytes` 两道上限约束。
- 旧记录没有 `elsewhere`，界面按「只有一处」渲染；`at` 的语义、`before`/`after` 取自第一处这一点都没有变。
- **消息序号只是那一次请求里的坐标**：下标在历史被压缩或截断后会变，同一条消息在不同请求里序号不同，所以它答不了「这是会话里的哪一步」。会话里的稳定坐标（轮次、步数）由 ADR-0030 补上，两者互补。
- **路径里的键可能本身就是敏感文本：已由 ADR-0029 修掉**。原先 `at`/`elsewhere` 的路径由 body 的原始键拼成、而键从不脱敏，所以密钥当键名时会经路径写进记录；ADR-0029 让键也走同一套查找器，记录里写的是发出时的占位符。
