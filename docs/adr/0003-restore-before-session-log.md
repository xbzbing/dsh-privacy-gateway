# ADR-0003：本地日志是否还原由开关决定，默认不还原

- 状态：Accepted（2026-10-28 拍板；2026-11-20 改为开关，默认不还原）
- 相关：`src/redact/restore.ts`、`src/dispatcher.ts`、`src/config.ts`、ADR-0001、ADR-0021

## Context

dispatcher 在 HTTP 层还原的是 adapter 收到的字节，agent loop 再从这些字节组装 assistant 消息和工具调用并落盘。user 消息则在用户发送时就已落盘，早于网关。所以还原在哪一层，直接决定会话日志里是真值还是占位符。

回复方向只有 HTTP 层这一个还原缝（ADR-0001：`agent/assistant-stream` 是只读发布，`llm/stream` 出站改不了），会话日志和 agent 拿到的内容出自同一批字节：日志里是占位符，agent 手里就是占位符；日志里是真值，agent 手里就是真值。

## Decision

增加一个开关，控制本地会话日志是否还原，默认不还原。

- 默认关闭：回复里的占位符不换回原值，占位符原样进会话日志，明文不进日志。
- 用户可以打开：占位符在日志落盘之前换回原值，agent 与日志拿到的都是真值。

开关是配置页上的 `restoreLog`，volatile 字段，改了即时生效（ADR-0021）。开关只管还原；脱敏、值表、脱敏记录与统计都不受它影响——记录里只有 placeholder、kind、首字符、长度，没有值本身（ADR-0008）。

## Consequences

- 默认下会话同步、备份、分享、导出带走的是占位符；agent 也只拿到占位符，「这个 token 为什么 401」这类要真值才能做的任务默认做不了，打开开关即可恢复。
- 打开开关后 agent 对真值无感，能把真值写进命令、粘进文件；代价是会话日志以及它的同步、备份、分享、导出带回真值。
- 还原打开时，还原后的真值会进入工具调用参数，包括发往 HTTP MCP 服务器的请求。注入内容诱导模型在工具参数里写出真实占位符并指向外部地址时，真值会被送出本机；toolGuard 可以告警或让那处不还原（ADR-0014），默认只记账。默认关闭时这条外带路径不存在。
- 还原打开时，压缩的回复要先解码再还原，否则占位符进日志：要还原的请求要求 `accept-encoding: identity`，仍收到压缩回复时解码后处理（ADR-0025）；关闭时不改这个头，压缩的回复原样穿过网关。
