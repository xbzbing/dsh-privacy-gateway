# ADR-0003：还原发生在会话日志之前，日志含真值

- 状态：Accepted（2026-10-28 拍板）
- 相关：`src/redact/restore.ts`、`src/dispatcher.ts`、ADR-0001

## Context

dispatcher 在 HTTP 层还原的是 adapter 收到的字节，agent loop 再从这些字节组装 assistant 消息和工具调用并落盘。user 消息则在用户发送时就已落盘，早于网关。所以还原在哪一层，直接决定会话日志里是真值还是占位符。

两种取舍：

- 还原（magpie 的做法）：agent 无感，能把真值写进命令、粘进文件；代价是日志里是真值。
- 不还原（dsh-mask 的做法）：明文永不进日志；代价是 agent 只拿到占位符，命令里用不了真值。

## Decision

还原，接受会话日志里是真值。补偿是每次替换都记账、可统计（记录里只有 placeholder、kind、首字符、长度，没有值本身）；记账随 P1 实现。

## Consequences

- agent 照常工作，模型是唯一看不到值的一方。「这个 token 为什么 401」这类任务模型做不了，需要白名单或临时关闭。
- 会话日志是明文：会话同步、备份、分享、导出带走的是真值。这是日志的属性，网关管不到，README 需要写明。
- 还原后的真值会进入工具调用参数，包括发往 HTTP MCP 服务器的请求。注入内容诱导模型在工具参数里写出真实占位符并指向外部地址时，真值会被送出本机；缓解方案尚未定（设计稿 R15）。
- 压缩的回复也要还原，否则占位符进日志：脱敏过的请求要求 `accept-encoding: identity`，仍收到压缩回复时解码后还原（ADR-0025）。
