# ADR-0031：短于 8 个字符的口令、明显是占位的写法，都不算值

- 状态：Accepted（2026-11-03）
- 相关：`src/redact/find.ts`、`src/redact/checks.ts`、`src/redact/known.ts`、`src/records.ts`、ADR-0008、ADR-0019、ADR-0028、ADR-0030

## Context

用户在统计卡上核对时发现两类「被脱敏的值」其实什么也没保护：

- 排查问题时他往对话里写了一个 `sk-proj-xxxxxxxx…`（20 个 x）的假 key，网关照样换成占位符、记一条记录，卡片显示「替换 1」。数字上像拦住了一次泄露，实际上那串东西本身就是「这里应该有个 key」的占位写法。
- `abc123`、`666666`、`888888` 这种 6 位口令也被记。它们随时能被爆破，遮住给的是一种并不存在的保护承诺；而且这么短的串在普通文本里到处都是，命中更多是噪声。

旧行为本身也不自洽：值表从来不把短于 8 个字符的值当作「已知值」去匹配（`known.ts` 的 `MIN_KNOWN`，否则短串会在普通文本里满屏命中），所以一个 6 位口令会被规则换掉一次，之后再也认不出来——既不还原，也不解释。

## Decision

- **短于 8 个字符的秘密不算值**。秘密类规则（`cat: 'secret'`：`API_KEY`、`TOKEN`、`PASSWORD`、`SECRET`、`PRIVATE_KEY`）命中的值，`find.ts` 的 `takes()` 先看长度，短于 `MIN_SECRET_CHARS = 8` 就不算：不发占位符、不记录、不进值表。检查放在 `takes()` 一处，所有规则、所有写法（URL 里的密码、`password=…`、中文「密码为…」）一次覆盖，并与 `MIN_KNOWN` 取同一个数——`test/rules.test.ts` 有一条断言盯着两者相等。
- **明显是占位写法的值不算值**。同一个地方过 `notATemplate()`：
  - 值里有 8 个以上相同字符连排：`sk-proj-xxxxxxxx…`、`AKIA0000…0000`、`ghp_xxxxxxxx…`。随机 key 出现 8 连排的概率低于 62⁻⁶ ≈ 1/5.7e10。
  - 值里自带「这是占位」的词：`your_api_key`、`your-key`、`your_token`、`example`、`placeholder`、`changeme`、`redacted`、`dummy`、`***`。`test` 故意不在此列：`sk_test_…` 是 Stripe 的**真**测试 key，必须照旧脱敏。
  - 长值只看首尾各 128 个字符：模板的破绽在两端，而整段扫描会把每次命中的开销放大——`'token='.repeat(8000)` 这种病态输入从基线 36 ms 涨到 154 ms，只看两端是 73 ms，`test/linear.test.ts` 守着这条预算。
- **个人数据和自定义词不受影响**：`EMAIL`、`PHONE`、`ID_CARD`、`BANK_CARD` 不是「能被爆破的口令」，`words` 是用户点名要遮的词，两者都不做长度或模板过滤。

## Consequences

- `abc123`、`666666`、`888888` 这类短口令原样发出，也不进记录；8 位以上（`postgres123`、`786kih24`）照旧脱敏。这是明确的产品选择：它本来就挡不住爆破，拦下来只让统计更好看、让文本更难读。日后要调，改 `MIN_SECRET_CHARS` 一个常量、同步那条相等断言即可。
- `sk-proj-xxxx…`、`AKIA0000000000000000`、`ghp_xxxxxxxx…` 这类写法不再被算作值，统计里的「替换」数回到真实水平。
- 代价：一个真 key 若恰好含 8 个相同字符连排、或在值里含 `example` 这类完整英文单词，会被放过。前者约 1/5.7e10，后者要求真 key 里出现完整英文单词，概率同样极低；权衡的取向是用户明确要的——宁可放过明显是占位的写法，也不要一个虚高的保护数字。
- 已知值（`known`）路径不变：已经在值表里的值照旧按已知值匹配，只是短于 8 的本来就进不了值表，这条本来就成立。
- 记录里与这些值相关的条目一起消失：它们从未被换掉，也就没有占位符、没有位置、没有上下文，`values` 只留真正被遮住的值。
