# ADR-0024：记录里的每个值带上位置和前后文字

- 状态：Accepted（2026-10-31）
- 相关：`src/redact/mask.ts`、`src/records.ts`、`src/config.ts`、`src/client/StatsParts.ts`、`src/client/view.ts`、ADR-0008、ADR-0019、ADR-0021

## Context

记录明细里每个值只有占位符、kind、开头和长度。用户看到 `sk-proj-AbCd…45` 被替换了 4 次，但看不出是在哪段对话里、什么场合被替换的，无法判断这次替换对不对。

## Decision

- 每个值记下第一次出现的位置和前后文字（后续：ADR-0028 让每个值再记其余位置；`at`/`before`/`after` 仍取自第一处）：
  - `at`：在请求 body 里的点分路径（`messages.3.content.0.text`），以及路径上最内层对象的 `role` 和 `type`。
  - `before` / `after`：替换处前后各约 80 个字符，连续空白合成一个空格，被截断的一侧加 `…`。
- 前后文字以**发出的内容**为基础，另做安全投影后截取：被脱敏的值保留占位符或同形假 key，warn 值也换成占位符；受保护片段在上下文副本里省略为 `…`，不把发送豁免带进记录。发送 body 仍逐字节保持这些片段，vendorView 的如实副本例外不变（ADR-0016）。
- `at` 的展示路径沿脱敏键或 warn 键的安全名称传播到后代；内部保护/参数/宿主文本判断使用无损路径分段，不从点分展示路径推断树结构。
- 记录明细里，每个值下面多一行：位置标签（系统提示、用户消息、模型回复、工具调用、工具结果、其他），然后是「前文 + 高亮的占位符 + 后文」。鼠标悬停在位置标签上显示完整路径。
- 新增配置项 `recordContext`，默认开启，volatile，放在配置页「记录」组。关闭后新记录不带位置和前后文字，旧记录不变。

## Consequences

- 记录不再只是元信息：前后文字是对话内容的片段，会写进状态目录的 `masking/`（2026-11-01 起按实例隔离，见 ADR-0027）。这些片段与模型服务收到的内容相同，不含被脱敏的值。没开个人信息脱敏时，邮箱、手机号等会原样出现在片段里，配置页的说明写明了这一点。
- 每个值多约 250 字节。按每条记录几个值算，磁盘占用的增加在 `keepMegabytes` 的范围内可以接受。
- 旧记录没有这些字段，明细里不显示这一行。
