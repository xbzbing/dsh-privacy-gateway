# ADR-0022：统计卡重新排版；「清空数据」二次确认后清空历史

- 状态：Accepted（2026-10-31）
- 相关：`src/client/StatsCard.ts`、`src/client/StatsParts.ts`、`src/client/styles.ts`、`src/records.ts`、`src/remote.ts`、`src/index.ts`、ADR-0008、ADR-0016、ADR-0017

## Context

统计卡原先的写法是自绘的：粗边框的告警框、松散的数字、整行的大条形图、没有表头的记录列表，和 Web 壳其他页面不像。用户还要一个按钮，能把历史数据清掉。

## Decision

### 排版

- 头部一行：左边标题、状态 `Tag`（开启为 success，关闭为 warning）、本会话 `Tag`、值表大小；右边是时间范围 `SegmentedControl`（今日 / 7 天 / 30 天）、刷新按钮（图标）、「清空数据」。
- 告警改为浅色底的单行提示，前面带警告图标，不再用粗边框。
- 计数放进一条浅底的指标带，格子之间用细线分隔；平均和最长脱敏耗时也作为一格放进去，不再单独占一行。
- 三个分布各占一块细线框，每项一行：名称和计数在上，4px 细条在下。
- 最近记录改为带表头的表格：时间、模型 / host（两行）、来源、替换、还原；行首的箭头展开后转 90°。窄屏隐藏「来源」列。分页用图标按钮和「页 / 总页」。
- 颜色、字号、细线都用 `--dsw-alias-*` 和官方组件，与官方「统计」标签页的视觉一致。

### 清空数据

- Remote 新增 `privacyGateway/reset`。宿主执行 `RecordStore.reset(recordDir)`：等正在读盘和写盘的操作结束，丢掉排队未写的记录，清空内存里的记录与每日汇总、失败连续计数，删除记录目录里所有 `YYYY-MM-DD.jsonl`，目录里的其他文件不动；再清空厂商视角副本。返回删除的文件数。
- 不管 `record` 当前开没开，都清记录目录：盘上的历史正是要清的东西。清空后不会再把盘上的天数读回统计。
- 值表不清：正在进行的请求，回复还要靠它还原。
- 按钮只出现在插件详情页的统计卡上。会话标签页里的统计只看本会话，而清空作用于所有会话，放在那里容易误会。
- 确认用 Web 壳的 `RiskConfirmation`：说明会删什么、无法恢复，勾上「我知道清空后无法恢复」才能点「清空」。完成后卡片顶部提示删除了几个文件，并重新读取。

## Consequences

- 清空无法撤销，没有备份。
- 清空和新记录同时发生时，等待读盘、写盘结束期间加入的记录也会被清掉；删除文件期间加入的记录留在内存里，文件删完后才写盘。清空进行时不写盘，内存里的记录与盘上的始终一致。
- 不提供 Remote source 的 `reset` 时，服务拒绝调用，不假装清空成功。

## 补充（2026-10-31）：记录列表的结构与刷新失败

- 最近记录在视觉上仍是带表头的表格，结构上是一个列表（`ul` / `li`），每行是一个展开按钮，按钮的无障碍名称逐列带上列名（如「时间：09:05:07，替换：3」）；表头只给眼睛看（`aria-hidden`）。按钮行放进 `role=table` 不合规范，所以不用表格角色。
- 刷新失败时，卡片保留上次读到的数据，但在顶部提示「刷新失败（原因），下面是上次读到的数据，可能已过期」，不再悄悄沿用旧数据；从没读到过数据时显示读不到的原因。
- host 端回答的 `overview` 先按字段校验、补齐：某个范围缺字段时按 0 计，画不出的记录丢掉，host 与页面版本不一致时卡片不会因此崩掉。
